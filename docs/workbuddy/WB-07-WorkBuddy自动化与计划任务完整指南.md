# WB-07 WorkBuddy 定时任务与远程助理：让重复工作按计划执行

老金写这篇教程的目的——让你学会用**自动化**把重复活交出去。学完这篇，你的 WorkBuddy 就能每天定时出汇报、监控到异常自动通知你、你在微信里一句话就能远程触发它干活——你睡觉它干活，你下班它接着干。

## 先搞清：自动化是什么、有哪几种

这篇讲两种日常用法，老金先给你认认脸：

```text
1. 定时任务：到点就跑（每天 9 点出汇报、每周一 10 点出周报）
2. 远程任务：你在微信/企业微信里发指令，让在线的电脑干活
```

定时任务可以先筛选再汇总——比如「每天 9 点查邮件，整理待处理的紧急邮件，再推送检查结果」。检查发生在约定时间，通知的及时程度取决于检查周期。[官方自动化说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Automation-Guide)当前确认的是按时间规则触发；邮件连接器负责读取邮箱，微信远程指令则通过已连接的助理通道发起任务。

**自动化的核心价值**：

```text
✅ 解放重复劳动（每天必做的汇总、监控、汇报）
✅ 跨时段工作（你下班它继续干、你睡觉它守夜）
✅ 跨设备触发（手机一句话，桌面端开始干活）
✅ 闭环交付（任务跑完自动通知你，不用盯着）
```

**老金的提醒**：自动化是双刃剑。它能解放你，也能在配错时持续浪费积分、误发消息、误删数据。所以这篇老金会重点讲**怎么配得安全**。

准备清单：

```text
✅ WB-04~06 都学完，会用技能/连接器/知识库（自动化要组合它们）
✅ 想清楚一件你天天干的重复活（汇报、监控、提醒都行）
✅ 账号有积分（自动化会持续消耗，留意余额）
✅ 记下可接受的积分预算，知道在哪查看实际用量；临近预算时手动检查和停用不必要任务
```

## 第一步：建你的第一个定时任务（15 分钟）

老金带你建一个所有人都能用上的——**每天早上 9 点自动生成"昨日工作摘要"**。

### 1.1 找到定时任务入口

主界面找**定时任务**入口（5.5.4 起的正式叫法，更早的版本叫「自动化」）。点进去你会看到已建任务和运行记录。

### 1.2 新建定时任务

点击新增任务按钮（官方旧文档写作「添加自动化」，按钮文字以当前界面为准），填写这些配置项：

```text
名称：每日 9 点昨日工作摘要
提示词：基于我的"工作日志"资料库，总结昨天完成的事、未完成的事、
        今天要优先处理的事。生成"昨日工作摘要"，保存到指定工作空间。
工作空间：选择保存摘要的目录
权限模式：先用默认权限
模型和技能：选择当前可用的模型，按需勾选写作技能
定时规则：每天上午 9:00
结果通知：按需打开"推送到小程序"或"推送到企业微信 bot"，完成通道绑定
最后：保存任务，确认处于启用状态
```

### 1.3 第一次跑前的预演

任务保存后，**别等明天 9 点**，先手动跑一次验证：

```text
在定时任务列表（旧版叫自动化列表）找到这个任务，点"立即运行"或"测试运行"。
```

观察整个流程跑通没：

```text
✅ 它能不能读到你的工作日志（知识库检索成功）
✅ 它能不能生成摘要（专家产出正常）
✅ 它能不能通过所选通知通道推送结果
✅ 它能不能把摘要保存到指定工作空间
```

任何一步失败，看错误提示修。

### 1.4 等到明天 9 点看效果

预演跑通后，等明天 9 点（或你设的触发时间），看你选的小程序或企业微信通知通道是不是真的收到了摘要。

```text
如果收到 → 恭喜，你的第一个定时任务上线了
如果没收到 → 看下面排查
```

### 1.5 卡住了怎么办

```text
❌ 任务没在指定时间跑
   → 核对任务显示的执行时间、时区与系统时间
   → 检查任务是不是"已启用"状态
   → 检查本地电脑、网络和 App 是否在线；需要熄屏继续时检查"允许锁屏运行"档位
   → 看任务日志，是不是跑了但失败了

❌ 跑了但推送没收到
   → 检查任务的推送开关和已绑定通知通道（通道断开了就推不出）
   → 检查推送目标对不对（企业微信 vs 个人微信）
   → 检查通知权限（手机/电脑是不是禁了 WorkBuddy 通知）

❌ 跑了但产出是空的 / 错的
   → 知识库检索没找到东西（资料范围或问法要调）
   → 专家任务描述太模糊（任务模板要写更具体）
   → 连接器读不到数据（邮箱空、文档没内容）
```

## 第二步：定时巡检任务

### 2.1 定时检查，再汇总结果

定时任务可以先查资料，再汇总本次检查结果。典型场景：

```text
- 每天 9 点检查邮件 → 汇总尚未处理的紧急邮件
- 每天下班前检查指定腾讯文档 → 有变更才整理摘要
- 每周一检查项目待办 → 汇总逾期事项
```

### 2.2 建一个紧急邮件巡检任务

老金带你建一个：**每天上午 9 点检查新邮件，把需要处理的紧急邮件汇总后推送到企业微信**。先确认 QQ 邮箱连接器能读取邮件、企业微信通知通道已经绑定。

```text
第一步：填写任务和定时规则
   → 名称：紧急邮件巡检
   → 定时规则：每天上午 9:00

第二步：选择能力并填写提示词
   → 启用已授权的 QQ 邮箱连接器
   → 检查上次成功巡检以来的新邮件，筛选标题或正文含"紧急"的邮件
   → 每封用 100 字以内说明核心诉求、我需要做什么、最晚回复时间
   → 把检查时间和已处理邮件记录存到指定工作空间，避免下次重复通知
   → 没有新紧急邮件时，在运行记录中说明结果

第三步：设置输出
   → 保存结果到工作空间，打开"推送到企业微信 bot"
   → 确认所选 bot 已连接，再保存并手动试跑一次

第四步：保存启用
```

### 2.3 你会看到什么效果

下一次定时检查发现紧急邮件后，企业微信会收到类似内容：

```text
🚨 紧急邮件提醒

发件人：[某人]
主题：[邮件标题]
核心诉求：[一句话]
你要做：[具体动作]
建议回复时间：[今天下班前 / 立刻]

完整邮件请打开邮箱或回到 WorkBuddy 继续查询。
```

这种做法适合周期性巡检。邮件可能在两次检查之间到达，因此不能把它当成秒级告警。通过任务通知 bot 推送的是结果通知，不会自动把本次执行内容写进助理上下文，直接回复「详情」也不一定能接上这次任务。

### 2.4 巡检任务的注意点

```text
⚠️ 筛选条件别太宽，也别只靠一个关键词判断重要程度
⚠️ 检查周期要符合你的时效要求，并计入积分预算
⚠️ 保留检查时间和处理记录，验证重复运行不会重复通知
⚠️ 先确认运行记录和推送结果，再开启长期定时执行
```

## 第三步：远程触发——微信里让桌面干活

### 3.1 这是什么

你在手机微信/企业微信里给 WorkBuddy 发一句话，它能触发桌面端的复杂任务。比如：

```text
- 通勤路上发"生成今天的会议准备清单" → 桌面端开始干
- 出差时发"整理一下这个客户的资料发给我" → 桌面端跑完推回你手机
- 半夜突然想到件事发"明天提醒我联系 XX" → 加进待办
```

### 3.2 怎么用

前提：在**头像 → 设置 → 助理设置**中，按对应平台指南完成微信助理或企微助理绑定，并让电脑、网络和 WorkBuddy 保持在线。能收到结果通知，不等于已经配好可以下发任务的助理。配置方式见 [官方助理说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Assistant)。

```text
第一步：在助理设置中确认平台已经绑定，电脑与 WorkBuddy 在线
第二步：到已绑定的微信助理或企微机器人对话发送一个小任务
第三步：在 WorkBuddy 助理页核对收到的材料与执行记录
第四步：完成后检查手机收到的结果，区分助理回复与定时任务的结果通知
```

### 3.3 实战：通勤路上准备早会

```text
你在地铁上，9 点要开早会。
打开企业微信给 WorkBuddy 发：
  "9 点要开部门早会，基于我昨天的工作日志，
   准备一份 3 分钟的发言稿，重点说我昨天的进展和今天的计划。
   推到我的企业微信，我等下到公司就能直接念。"

完成后核对企业微信实际收到的发言稿与引用记录；耗时取决于本次任务，不能保证到公司前已经完成。
```

这就是远程触发的威力——把碎片时间利用起来。

### 3.4 远程触发的限制

```text
⚠️ 本地桌面任务需要电脑和 App 在线；关机或系统休眠时无法继续执行
⚠️ 熄屏后要继续运行，到头像 → 设置 → 通用选择相应的锁屏运行档位
⚠️ 远程任务消耗积分（手机指令也算一次完整任务）
⚠️ 涉及大文件的远程任务会慢（建议小任务用）
⚠️ 多人共用账号时远程触发要协调（别互相覆盖任务）
```

## 第四步：自动化任务的管理和监控

老金这一步讲怎么管你已经建的自动化，避免它们在后台乱跑。

### 4.1 任务面板

进入**定时任务**入口（旧版叫「自动化」），你看到所有任务列表。每个任务卡片通常显示：

```text
- 任务名 + 启用/禁用开关
- 上次运行时间 + 状态（成功/失败）
- 累计运行次数 + 消耗积分
- 最近一次的产出预览
```

### 4.2 日常监控

老金建议你**每周检查一次**：

```text
✅ 哪些任务这周跑过、成功没
✅ 失败的任务是什么原因（看日志）
✅ 消耗积分是否异常（突然变多可能配错了）
✅ 还需要的任务继续开，不需要的关掉
```

### 4.3 任务的暂停、修改、删除

```text
- 暂时不用 → 点"禁用"（保留配置，下次再开）
- 配置要改 → 点"编辑"（改触发条件、执行内容、输出方式）
- 彻底不用 → 点"删除"（清理掉，避免堆积）
```

### 4.4 任务失败通知

关键任务要定期检查运行记录，并启用已绑定的小程序或企业微信结果推送。用缺少测试输入文件等可恢复的失败试跑一次，确认当前版本是否推送失败状态；成功时能收到通知，不代表失败时一定会提醒。

## 第五步：自动化的安全和防坑

老金这一步是为你好——自动化配错可能造成持续浪费或事故。

### 5.1 积分失控防护

```text
✅ 记下自己的可接受预算，每周查看实际用量；接近预算时手动停用不必要的定时任务
✅ 当前账号若提供预算限制，再按页面配置，并用小任务验证它是否会阻止超额执行
✅ 缩小高消耗任务的材料与处理范围，先观察试跑用量
✅ 区分提示词中的预算要求与产品强制限额；只写“最多 X 积分”不能证明会自动停止
```

### 5.2 误操作防护

```text
🚫 自动化任务里别配"删除"动作（除非绝对必要）
🚫 别配"自动回复邮件/消息"（容易误发，至少要人审一遍）
🚫 别配"修改生产文档/代码"（自动改的风险大）
✅ 高风险动作改成"草稿模式"：跑完产出草稿，人审后再发
```

### 5.3 出事了怎么办

```text
🚨 自动化误发了消息 / 误删了文件
   → 停用任务后检查是否还有当前执行或后台命令，分别停止，并核对运行记录
   → 撤回/恢复（消息撤回、文件从回收站恢复、文档版本回滚）
   → 检查任务配置，找出是哪一步错了
   → 修好后先"测试运行"，确认正常再正式启用
```

### 5.4 团队自动化的协作

```text
- 复用任务：当前页面有分享配置入口时再使用；否则分享任务说明，由同事在自己的账号配置
- 任务负责人：明确谁维护材料、检查运行记录与处理失败
- 人工审阅：外发或批量操作先产出草稿，按团队已有流程确认；不假定每个套餐都有内置审批按钮
- 避免重叠：共享文件或通知目标先协调，减少重复执行
```

## 常见问题

**Q1：自动化任务要电脑一直开机吗？**
本章按桌面端创建和执行的定时任务练习，保持电脑、网络和 WorkBuddy 在线，并检查系统休眠设置。不能仅凭任务用了连接器，就判断它已经在云端独立调度。若账号另有云端执行入口，先按该入口的官方说明确认运行位置、调度条件和通知方式，再判断是否可以关机。远程助理控制电脑时，也需要电脑开机并运行 WorkBuddy。

**Q2：自动化消耗积分快吗？**
看任务复杂度。简单的定时通知消耗少，复杂的专家团 + 多连接器任务消耗大。建议先用低成本任务试，看一周消耗多少，再决定是否扩。

**Q3：任务失败了会自动重试吗？**
失败后先查运行记录与错误原因，再按当前页面提供的重试入口继续。不要默认会自动重试固定次数，也不要仅凭成功通知推断失败一定通知；按 4.4 节用可恢复的失败试跑核对。

**Q4：能同时跑多个自动化任务吗？**
能。但同时跑太多会拖慢、可能冲突。建议错开高峰（别所有任务都设 9 点），同一个资源的任务别重叠（都在改同一份文档会冲突）。

**Q5：自动化任务能分享给同事吗？**
查看当前任务页是否提供分享或复制配置。没有该入口时，可以分享任务说明与提示词，让同事在自己的账号重新配置；引用的资料、连接器和通知通道需要各自授权，不能靠分享文本继承你的访问权。

**Q6：远程触发算谁的积分？**
查看执行任务的 WorkBuddy 账号、所属套餐和实际用量记录，不按发送消息的人推断固定扣费对象。团队先确定任务归属与预算，避免共用账号时分不清消耗。

**Q7：自动化任务会被公司审计吗？**
企业版下，管理员通常能看到你建了什么任务、消耗多少积分、调用什么数据。涉及公司数据的任务要符合公司政策，别私建涉及客户/财务的自动化。
