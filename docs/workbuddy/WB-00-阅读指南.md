## 这份文档是写给谁的？

老金我把 WorkBuddy 系列的阅读路线拆得这么细，是为了让没接触过 AI 办公 Agent 的人也知道先跑通哪一步、卡住时查哪一层。

不管你是刚接触 AI 的小白、想把日常办公交给 AI 的上班族，还是想给团队部署一套 AI 办公规范的负责人，这套教程都能帮到你。本系列共 **11 篇**（本篇 **WB-00 阅读指南** + **WB-01～WB-10 正文**），不必逐篇通读。这篇指南帮你找到最适合自己的阅读路径。

> **2026-08-06 版本口径**：WorkBuddy 是腾讯云出品的 AI Agent 桌面工作站（与 CodeBuddy 同团队同账号体系），本系列按 2026-08-06 可查官方文档与 App 行为修订。WorkBuddy 没有 semver，版本号、菜单名、价格一律以本机 App 关于页和官网（workbuddy.ai / codebuddy.cn/work）为准。

## 术语表（先看这个）

在开始之前，先搞懂几个核心概念。后面所有文档都会用到这些词：

| 术语 | 一句话解释 | 类比 |
|------|-----------|------|
| **WorkBuddy** | 腾讯云出品的 AI Agent 桌面工作站，"一句话让 AI 替你上班" | 相当于你雇了一个 AI 办公团队 |
| **CodeBuddy** | 腾讯云的编程 Agent 产品，与 WorkBuddy 同账号同团队 | "CodeBuddy 管开发，WorkBuddy 管办公" |
| **任务（Task）** | 你用一句话描述给 WorkBuddy 的一件事 | 相当于给员工下的一份工单 |
| **Agent** | WorkBuddy 里负责某类子任务的执行单元 | 相当于团队里的一个专员 |
| **Artifacts** | 任务产出的可复用物件（文档、表格、幻灯片、代码片段） | 相当于员工的交付物 |
| **Coding Mode** | WorkBuddy 内置的编程模式，专门处理写代码类任务 | 相当于团队里技术员的工位 |
| **集成（Integration）** | WorkBuddy 与外部系统的连接（GitHub、GitLab、企业微信、QQ 等） | 相当于员工的外联通讯录 |
| **计划任务** | 周期性或定时触发的自动化任务 | 相当于员工的定期汇报机制 |
| **工作区** | WorkBuddy 桌面 App 里你当前正在处理的任务集合 | 相当于员工的办公桌面 |
| **审批** | 高风险动作执行前需要人确认的环节 | 相当于财务的签字流程 |

## 阅读路线图

### 先判断你要解决什么问题

WorkBuddy 不是单纯的聊天网页，也不是只会写代码的 CLI。它更像一个能交付成品的办公团队：上面接你的需求，中间多 Agent 并行干活，下面产出 Word / Excel / PPT / 代码。学习时不要一上来追所有功能，先判断自己今天要解决哪个问题。

```text
如果你只是想体验一下 AI 办公：
先看 WB-01、WB-02，跑通第一个任务。

如果你想把重复汇报交给 AI：
先看 WB-02、WB-03、WB-04，再回头看 WB-07 的计划任务。

如果你是开发者，想用 WorkBuddy 写代码：
先看 WB-02、WB-03、WB-05、WB-06。

如果你是团队负责人，想给团队部署：
先看 WB-02、WB-03、WB-09，再回头看 WB-07、WB-08。

如果你在多个 AI 工具之间纠结：
直接看 WB-10，按任务选工具。
```

### 🚀 路线一：小白速通（30 分钟上手）

只想最快跑起来？按这个顺序，跳过所有标注"可跳过"的章节：

```text
WB-01 项目介绍（只看前 3 节，了解 WorkBuddy 是什么）
    ↓
WB-02 安装登录（跟着"快速安装"章节操作）
    ↓
WB-03 桌面工作流（跟一遍第一个任务工坊）
    ↓
搞定！你已经能让 AI 替你交一份办公产物了 🎉
```

之后遇到问题去看对应的 FAQ 或下一章。

速通路线结束后，不要马上接 GitHub、企业微信、计划任务。先用一个真实小任务跑通 Artifacts、Files、Changes 四面板，确认 App、账号、Agent 都正常。否则集成失败时，你会分不清是 App 问题、账号问题，还是集成配置问题。

### 🔧 路线二：日常办公（2-3 小时）

想在汇报、调研、写文档里真用起来？在路线一的基础上加：

```text
路线一完成后
    ↓
WB-04 深度研究与数据分析（让 AI 出 Excel + PPT）
    ↓
WB-07 计划任务（让 AI 定时跑汇报）
    ↓
WB-08 办公协同（推到企业微信/QQ/手机）
```

### 🏗️ 路线三：开发协作（半天）

开发者想把 WorkBuddy 接进代码工作流？在路线一的基础上加：

```text
路线一完成后
    ↓
WB-05 Coding Mode（写代码、跑测试、起 dev server）
    ↓
WB-06 GitHub/GitLab 集成（clone、改、发 PR）
    ↓
WB-10 与 Claude Code/Codex 对比（什么时候用哪个）
```

### 🔒 路线四：企业落地（需要 IT 经验）

要给团队部署 WorkBuddy？

```text
路线二完成后
    ↓
WB-09 企业安全与权限基线（审批、沙盒、数据边界、计费）
    ↓
WB-07 计划任务（团队级自动化）
    ↓
WB-08 办公协同（企业微信等 IM 分发）
```

企业路线里，安全边界是能否上线的前置条件。只要涉及多人共用、敏感数据、对外发布，至少要确认审批策略、数据驻留、账号席位和审计日志。

## 第一周学习计划

如果你想把 WorkBuddy 学成真正可用的工具，可以按下面 5 天推进。

### 第 1 天：跑通 App 和账号

目标确认本机能运行、能登录、能发出第一个任务。

你应该能回答：

```text
- App 装在哪里？版本号是多少（关于页）？
- 用什么账号登录（个人 Pro / 企业 Team）？
- 能否发出一句话任务并收到 Artifacts 产出？
- 失败时去哪看日志或提示？
```

### 第 2 天：跑通一个真实办公任务

选一个低风险的真实任务，比如"把这份会议纪要整理成 Word"。

这一天只确认任务输入、Agent 并行、Artifacts 产出这条链路。不要同时接 GitHub、企业微信、计划任务。

### 第 3 天：试一次深度研究或数据分析

用 WB-04 的工坊，让 AI 做一份小调研或数据表。

观察多 Agent 并行调度、来源引用、产出格式。

### 第 4 天：加一个集成或计划任务

选一个低风险入口：GitHub（开发者）或企业微信（办公），或者一个每天定时的计划任务。

不要一次开所有集成。先开一个，观察它怎么工作、怎么停、怎么撤销。

### 第 5 天：做一次安全检查

如果你是团队负责人，检查账号席位、审批策略、数据边界、敏感信息外发规则。

这一天的目标是建立安全基线，而不是继续加功能。

## 遇到问题时怎么读文档

不要直接在 FAQ 里搜索一个报错词就结束。更稳的排查路线是：

```text
装不上 / 登录失败：
先看 WB-02 安装登录，再查官方帮助中心。

能登录但任务不产出：
先看 WB-03 桌面工作流，确认任务描述是否清晰、Agent 是否被触发。

产出质量差：
先看 WB-04 深度研究，看是否需要分步下任务、给参考素材。

Coding Mode 不执行命令：
先看 WB-05 编程模式，确认权限和沙盒。

GitHub/IM 集成失败：
先看 WB-06 或 WB-08，再查对应平台凭据。

担心数据外泄或费用失控：
先看 WB-09 企业安全。
```

每次排障都记录四件事：

```text
1. 当前任务描述。
2. 当前 App 版本（关于页）。
3. 失败时的提示或日志关键行。
4. 你已经排除了什么。
```

这样你在官方群、issue 或问其他 AI 时，别人能快速判断问题在哪一层。

## 三个典型学习场景

### 场景一：个人办公助手

推荐路线：

```text
WB-01 -> WB-02 -> WB-03 -> WB-04 -> WB-07
```

重点：

```text
- 任务描述清楚（一句话讲清目标、范围、交付物）。
- Artifacts 产出可复用。
- 计划任务只保存非敏感汇报。
- 个人账号 vs 企业账号的边界要清楚。
```

不要急着做：

```text
- 企业级集成。
- 自动化外发到 IM 群。
- 让 AI 直接操作敏感数据源。
```

### 场景二：团队办公自动化

推荐路线：

```text
WB-01 -> WB-02 -> WB-03 -> WB-08 -> WB-09 -> WB-07
```

重点：

```text
- 先明确谁能用、账号席位怎么算。
- 团队任务和个人任务分开。
- IM 分发要有白名单。
- 计划任务要有 owner。
```

不要急着做：

```text
- 让 AI 自动发对外消息。
- 把所有内部文档一次性塞给 AI。
- 多人同时改同一份 Artifacts。
```

### 场景三：开发团队用 Coding Mode

推荐路线：

```text
WB-01 -> WB-02 -> WB-05 -> WB-06 -> WB-10
```

重点：

```text
- Coding Mode 的权限和沙盒。
- GitHub 集成的分支策略。
- 与 Claude Code / Codex 的边界（WB-10）。
```

不要急着做：

```text
- 让 WorkBuddy 同时干办公和写代码两类任务。
- 在 WorkBuddy 里改生产仓库主干。
```

读教程不是只留下"我看过了"。每章读完最好留下一个具体产物。

| WB-04 深度研究 | 一份 AI 产出的调研报告或数据表 |

## 版本差异提醒

WorkBuddy 更新很快，你本机 App 的菜单、按钮、字段可能和文档略有差异。遇到这种情况，先看当前 App 的帮助/关于页，而不是硬套文档里的描述。

如果帮助输出和教程不同，以当前安装版本为准，再把差异记录到自己的 Runbook。教程负责教你理解链路和排查方法，具体参数要跟随你正在运行的版本。

记录差异时也写上日期和版本号，避免以后把旧环境经验误当成当前状态。
