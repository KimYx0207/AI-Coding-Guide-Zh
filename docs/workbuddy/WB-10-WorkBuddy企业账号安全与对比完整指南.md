## 第一部分：账号和积分体系

老金先把账号体系彻底讲清，因为这是掏钱决策和安全管理的地基。

### 1.1 三层账号形态

WorkBuddy 的账号分三层，对应不同人群：

| 形态 | 给谁 | 核心特征 |
|---|---|---|
| **个人版** | 个人用户、自由职业者、试用 | 单账号、订阅制、跟 CodeBuddy 共享积分 |
| **企业 SaaS 版** | 团队、小公司、中型企业 | 按席位计费、集中管理、团队共享 |
| **专有云企业版** | 大企业、强合规需求 | 私有部署、数据驻留可控、单价更高 |

### 1.2 WorkBuddy 和 CodeBuddy 的账号关系

老金再强调一次（很重要）：

```text
- 同一个腾讯账号、同一套积分池
- 订一份，两个产品通常都能用
- 不用分别注册、分别付费
```

所以你看到 WorkBuddy 的定价，可能跟 CodeBuddy 是同一套——别被两个产品名搞混。

### 1.4 积分机制（必懂）

> **入口提示**：5.4.7 起设置里有独立的「**订阅和用量**」页，套餐概览、分类积分、资源包明细都在这一页，也能直接在 App 内购积分和管理自动续费。管账号的人先把这一页找到。

**积分**是 WorkBuddy 的消耗单位，类似游戏钻石。规则：

```text
- 每月按套餐给积分额度（体验版少、付费档多）
- 按模型和任务的实际处理量消耗积分，不能按专家数量套用固定倍数
- 不同模型的消耗规则不同，以当前「订阅和用量」与定价说明为准
- 用完了任务跑不动，等下月重置或加购
```

**积分消耗优先级**（先扣哪个）：

```text
1. 免费体验额度（最先扣）
2. 赠送积分（按到期顺序扣）
3. 付费积分（最后扣）
```

### 1.5 怎么选账号

```text
个人尝鲜 → 体验版跑通，再决定升不升标准版
个人重度 → 标准版月付试一个月，顺手转年付或连续包年；积分不够先买加量包，别急着升档
小团队（5-20 人）→ SaaS 企业旗舰版，按席位算清
中大型团队 → SaaS 企业旗舰版 + 团队管理
大企业 + 合规 → 专有云企业专享版（100 席起购），找腾讯销售谈
不确定 → 先个人版摸清，再决定升级
```

## 第二部分：企业部署和安全

这部分主要给团队负责人、IT 管理员看。

### 2.1 企业版的团队管理

采购时，把以下管理需求逐项列给供应商，确认所购版本实际支持什么：

```text
- 席位开通、停用与集中付费怎样管理
- 专家、技能、连接器和资料空间的权限怎样配置
- 审计能查看哪些操作、用量和数据，保留多久
- 部门或项目的数据隔离如何实现
- 是否支持公司现有的 SSO，以及适用条件
```

请对方提供对应版本的操作文档或合同条款，再安排小范围验证；不能把这份采购清单当作每个企业套餐都已经提供的按钮。

**项目协作与企业套餐分别确认**：当前官方项目说明支持共享指令、资料和能力配置，连接器有管理员配置的公共授权与成员各自配置的个人授权。公共票据会被项目成员共同使用，个人授权不共享票据；先确认服务账号的用途和成员范围。不要从项目里能共享任务，推导企业后台已经提供全量审计或审批。

### 2.2 专有云版的特点

专有云（私有部署）适合：

```text
✅ 金融、政企、医疗等强合规行业
✅ 希望控制数据处理位置，需要逐项核对模型、工具与外部调用的数据流向
✅ 要对接内部系统，需要确认当前版本的连接方式与实施范围
✅ 有审计与权限要求，需要把可记录的操作和控制范围写入采购验收
```

代价：

```text
⚠️ 单价更高（316 元/人/月，且 100 席起购）
⚠️ 部署周期长（要腾讯团队配合）
⚠️ 维护成本（要有 IT 团队）
⚠️ 升级安排与维护责任要在实施方案中确认，不能默认每次都比 SaaS 慢
```

### 2.3 安全边界（必须划清）

老金把企业用 WorkBuddy 的安全边界划清，避免出事：

```text
🚫 别让 AI 直接处理真正机密
   - 客户身份证号、银行卡号、医疗记录
   - 未公开的财务核心数据、股权结构
   - 涉密政府数据、军工资质相关

⚠️ 涉及敏感数据时的正确做法
   - 先脱敏（去掉真实姓名、ID、金额）
   - 用私有部署（专有云版）
   - 限制授权范围（最小权限原则）
   - 配审计和告警

✅ 企业版必做的安全配置
   - 按已确认的审计范围定期检查运行与用量记录
   - 关键连接器按团队现有审批流程授权，不假定所有套餐均有内置审批
   - 确定定时任务预算与负责人，提供强制限额时验证实际作用
   - 共享资料定期核对正式版本与历史状态
   - 离职或换岗时同时处理账号、平台机器人和助理绑定
```

### 2.4 合规和隐私

签约前，逐项确认数据驻留位置、外部模型和连接器的数据流向、训练用途、审计可见范围、保留与删除期限，以及可导出的数据和格式。个人版、企业 SaaS、专有云和第三方服务可能适用不同条款，不能用“通常不训练”代替具体约定。

把供应商提供的版本文档、服务协议、隐私说明与书面合同交给公司负责的人核对。部署在指定网络或使用专有云，也不自动证明每个外部模型和工具调用都留在本地。

### 2.5 团队推广的策略

老金给团队负责人的推广建议：

```text
✅ 别一上来全员推开（风险大、消耗高）
✅ 找 3-5 个种子用户先试 2-4 周
✅ 让种子用户攒出团队专属专家团、知识库、自动化
✅ 出团队使用规范（哪些能干、哪些不能）
✅ 培训后再扩大到全员
✅ 每月 review 使用情况，优化配置
```

## 第三部分：四工具横向对比

老金这一节把 WorkBuddy 跟本仓库的其他三个主线做完整对比。**记住：没有谁替代谁，是不同人不同工具**。

### 3.1 四工具速览

| 工具 | 出品 | 给谁 | 形态 | 主入口 |
|---|---|---|---|---|
| **Claude Code** | Anthropic | 开发者 | CLI + IDE 扩展 + 桌面 App + Web | 按工作环境选择入口 |
| **Codex** | OpenAI | 开发者、团队 | App + CLI + Web + Cloud | 桌面 App |
| **OpenClaw** | Peter Steinberger（开源） | 技术用户、极客 | 自部署框架 | 消息平台 |
| **WorkBuddy** | 腾讯 | 办公人、中国团队 | 桌面 App + 微信 + 小程序 | 桌面 App |

### 3.2 详细对比表

| 维度 | Claude Code | Codex | OpenClaw | WorkBuddy |
|---|---|---|---|---|
| 常见任务重心 | 代码修改与开发工具链 | 代码任务、审查与多入口协作 | 自部署代理与消息通道 | 文档、报表、资料问答与办公任务 |
| 认证 | 支持适用的 Claude 订阅登录、Console 等方式，按账户条件选择 | ChatGPT 账号或适用的 API 认证 | 按部署配置模型提供商 | 官网登录页支持微信、手机号、邮箱、SSO 等方式 |
| 角色与分工 | 可使用子代理，按任务配置或选择 | 支持原生 subagents，可按请求、AGENTS.md 或技能中的委派要求使用 | 按代理与工作区配置 | 可从专家与专家团入手，核对当前卡片提供的能力 |
| 模型与数据边界 | 按所用服务、权限和工具确认 | 按所用入口、权限和工具确认 | 可配置 Ollama 等本地提供商；外部服务仍需单独检查 | 按工作空间、权限、连接器与所购版本确认 |
| 怎样试用 | 用现有测试验证一项小改动 | 核对变更、测试与任务分工 | 先验证模型、消息通道和工具调用 | 先做本系列的周报、订单与资料练习 |

表里比较的是使用入口和任务方式，没有统一基准测试，不提供主观星级胜负。认证与分工细节可查 [Claude Code 认证](https://code.claude.com/docs/en/authentication)、[Codex subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)、[OpenClaw Ollama](https://docs.openclaw.ai/providers/ollama) 和 [WorkBuddy 安装登录](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Installation-Win-Guide)。

### 3.3 按场景选工具

老金按典型场景给你选型建议：

```text
👨‍💻 写生产代码、大型重构、CI/CD
   → 用同一项小改动验证 Claude Code 或 Codex 与已有测试、审查和发布流程的配合

📋 做周报、调研、PPT、办公自动化
   → WorkBuddy（开箱即用、腾讯生态深度集成）

🇨🇳 国内团队、用企业微信、要中文友好
   → WorkBuddy（原生贴合）

🔧 想完全本地部署、零云依赖
   → 可评估 OpenClaw 与 Ollama 等本地模型方案，并检查每个工具和外部服务是否仍访问云端

🌍 海外团队、用 Slack/Notion/Stripe
   → Codex / Claude Code

🎓 教非技术同事用 AI
   → 先用 WorkBuddy 的现成材料练习，检查账号、菜单和成果是否适合这批同事

🧪 想试各种 AI 模型、深度定制
   → OpenClaw（开源灵活）
```

### 3.4 共存策略

**老金的核心观点：四工具可以共存，不二选一**。

```text
开发者本人：
   - 主力：Claude Code（写代码）
   - 辅助：WorkBuddy（写周报、调研、办公）
   - 协作：Codex（多入口、Cloud 长任务）

团队部署：
   - 技术团队：Claude Code + Codex
   - 业务团队：WorkBuddy
   - 数据敏感场景：先核对模型、工具和数据处理要求，再决定部署方案
   - 全公司：按部门分工具，不强制统一
```

### 3.5 一个多工具协作的流程示例

下面用虚构的产品发布会说明怎样分工，涉及 WorkBuddy、Claude Code 和 Codex 三款工具。这是流程设计示例，不是本课程记录的实测耗时或已完成交付。

```text
场景：产品发布会的全流程支持

1. 用 WorkBuddy 做市场调研（基于腾讯文档、QQ 邮件客户反馈）
   → 产出：竞品分析、目标用户画像

2. 用 WorkBuddy 写发布会 PPT 大纲和讲稿
   → 产出：PPT 草稿、主持人讲稿

3. 用 Claude Code 开发发布会现场的 demo 应用
   → 产出：可运行的 demo 代码

4. 用 Codex 做 PR（多入口、团队 Review）
   → 产出：合并到主分支的代码

5. 用 WorkBuddy 自动化：每天监控发布会相关舆情、媒体反馈
   → 产出：每日舆情简报推到企业微信

6. 发布会结束后，用 WorkBuddy 整理媒体采访记录、出复盘报告
   → 产出：复盘文档存腾讯文档
```

各步骤都要核对来源、变更和最终结果，再按自己的任务决定是否采用这套分工。

## 第四部分：你的选型决策清单

老金给你一份决策清单，按问题一步步选：

```text
Q1：你主要做什么？
   写代码 → Q2
   办公任务 → Q3
   都做 → Q2 + Q3 都答

Q2：（写代码）你的代码规模？
   小脚本、demo、偶尔写 → 先用 WB-09 小练习核对生成、运行与审阅过程
   日常生产开发 → Claude Code
   多入口、CI/CD、团队协作 → Codex（或 Claude Code + Codex 组合）

Q3：（办公任务）你的团队和环境？
   国内团队、用企业微信、要中文 → WorkBuddy
   海外团队、用 Slack → Codex / Claude Code
   要本地处理 → 核对本地模型与工具配置，不能只凭 OpenClaw 自部署就保证零云
   个人轻量用 → WorkBuddy 体验版试

Q4：你的预算和控制需求？
   能自行部署 → 评估 OpenClaw、本地设备成本与模型或外部服务费用
   个人付费、简单 → WorkBuddy 标准版
   团队付费、要治理 → Codex 或 WorkBuddy 企业版
   强合规、要私有 → WorkBuddy 专有云 或 OpenClaw 自部署

Q5：你/你团队的技术水平？
   非技术 → 从 WorkBuddy 的现成材料练习入手，再按实际完成情况判断
   懂一点、能配 → Codex / WorkBuddy
   专业开发者 → Claude Code
   极客、爱折腾 → OpenClaw
```

按这个清单走一遍，你或你团队的工具选择会清楚很多。

## 第五部分：WorkBuddy 系列总结

老金把整个 WorkBuddy 系列串一遍，帮你形成完整心智模型。

### 5.1 核心概念回顾

```text
专家       = 角色化 AI（人设 + 方法论 + 工具链）
专家团     = 多专家协同（团长自动拆解并行）
技能       = 可复用的任务方法、说明和必要工具，外部服务仍需依赖与授权
定时任务   = 按时间规则执行，本地任务需电脑、网络和 App 在线
连接器     = 在授权范围内访问外部服务，如 QQ 邮箱、腾讯文档和腾讯网盘
远程助理   = 从绑定的微信、企微等通道向在线电脑下发任务
```

知识库是补充——把你的资料喂给 AI 当依据。

### 5.2 学习路径回顾

```text
入门（必学）：
- WB-01 项目介绍：判断要不要用 WorkBuddy

核心（重点）：
- WB-03 专家与专家团：核心玩法
- WB-04 技能与技能市场：能力扩展
- WB-05 连接器与腾讯生态：生态集成
- WB-06 知识库：让 AI 有依据

进阶（按需）：
- WB-07 自动化：让 AI 自动跑
- WB-08 多端协同：跨设备接力
- WB-09 Coding Mode：偶尔写代码

决策（团队）：
- WB-10 企业账号、安全、对比：选型和部署
```

### 5.3 使用 WorkBuddy 的核心原则

老金给你五条原则，记住这五条你就能稳稳用：

```text
1. 按任务选工具：用同一项小任务核对结果、用量和现有工具链，再决定由哪款工具推进
2. 先轻后重：先用直接对话，再用单专家，最后才用专家团
3. 安全第一：敏感数据脱敏、最小授权、定期 review
4. 积分预算：留意消耗，避免专家团烧光配额
5. 攒下资产：把常用任务做成专属专家团、知识库、自动化
```

## 常见问题

**Q1：WorkBuddy 会替换掉我们团队的开发者工具吗？**
不会。开发者工具（Claude Code、Codex）和 WorkBuddy 是互补关系。技术团队继续用开发者工具，业务/办公团队用 WorkBuddy，按角色分配。

**Q2：企业版最便宜要多少钱？**
按本章 2026-09-14 的公开报价快照，SaaS 企业旗舰版是 198 元/人/月或 2,376 元/人/年，5 席年付合计 11,880 元；专有云快照为 316 元/人/月、100 席起购。这不是本日重新核实的最低采购价，当前价格、起购条件和另行实施费用以订单或书面报价确认。

**Q3：小团队有必要上企业版吗？**
先列管理需求：集中付费、账号与访问管理、共享资料、复用方法、审计记录等。逐项核对个人版和所购企业版本实际支持什么，再用少量账号验证；不要仅因套餐叫“企业版”就认为这些需求已全部满足。

**Q4：数据安全吗？会被腾讯拿去训练吗？**
按所购版本的服务协议、隐私说明和书面合同确认训练用途、保存期限与第三方数据流向。本教程没有取得你的企业合同，不能作统一保证；敏感材料是否接入，由公司允许的数据处理方式决定。

**Q5：能用 WorkBuddy 替代公司现有的 OA/CRM 吗？**
不能完全替代。WorkBuddy 是 AI 助手，不是 OA/CRM 系统。它能**辅助**你处理 OA/CRM 里的内容（通过连接器），但核心业务系统还是专业的 OA/CRM。

**Q6：本仓库的四条主线，老金自己用哪几个？**
老金写代码用 Claude Code，写教程和办公用 WorkBuddy，做长任务协作用 Codex，实验性项目偶尔用 OpenClaw。每个工具都有它的位置，不二选一。

**Q7：这套教程会持续更新吗？**
会。WorkBuddy 和其他三个工具都在快速迭代，老金会定期 review 和更新。你关注本仓库的提交记录或公众号"老金带你玩AI"就能跟上。

**Q8：学完这 11 篇我算 WorkBuddy 高手了吗？**
算入门到熟练。要成高手还要持续实战——把 WorkBuddy 真正用进你的日常工作，遇到问题查官方文档和社区，攒出自己的专家团和知识库。教程给你方法和起点，真正的能力是练出来的。
