## 你要做什么

这一篇你要完成三件事，做完你也就懂 WorkBuddy 了：

```text
✅ 召唤一个"专家"，让它用专业视角帮你完成一个真实任务
✅ 看清 WorkBuddy 和 Claude Code / Codex 的本质差别（不是哪个更强）
✅ 判断自己或团队属不属于它的目标用户
```

如果你还没装 App，先去看 WB-02 装好登号再回来。下面假设你已经能打开 WorkBuddy 桌面 App。

## 第 1 步：召唤一个专家（15 分钟体会 WorkBuddy 是什么）

老金把这一步放在最前面，是因为看十遍功能介绍都不如你自己召唤一个专家体会一次。

WorkBuddy 的核心机制是**专家**——给 AI 配一个领域角色（"人设 + 方法论 + 工具链"），让它用那个领域的专业视角干活。比如让"财务专家"看一份表格，跟让"通用 AI 助手"看同一份表格，得到的结论完全不一样。

### 1.1 操作路径

打开 WorkBuddy 桌面 App，按下面路径操作（**菜单名以本机 App 当前显示为准**）：

```text
左侧栏 → 专家（或"专家中心"）
    → 浏览专家列表（按行业分类）
    → 选一个适合你任务的专家卡片
    → 卡片上点 "召唤专家"
    → 进入对话界面
```

专家卡片会显示三样东西（官方文档原文）：**能力介绍、擅长领域、任务示例**。选专家时看这三栏，挑最贴你任务的那个。

### 1.2 第一次任务：让它帮你写一份周报

假设你选了"办公写作专家"或类似的专家。进入对话界面后，把这段 Prompt 粘进去（方括号里的内容换成你的）：

```text
我是 [岗位]，这周主要做了三件事：
1. [事项一，一句话]
2. [事项二，一句话]
3. [事项三，一句话]
下周计划：[一两个计划]

帮我把这些整理成一份可以直接发给领导的周报：
- 标题、本周进展、下周计划、需要协调的问题
- 语气专业，不啰嗦
- 控制在 300 字以内
```

### 1.3 你应该看到什么

```text
- AI 用专家视角回复（措辞、结构、侧重点都贴你选的专家领域）
- 产出一份完整周报，包含标题、进展、计划、问题四块
- 可以直接复制到企业微信 / 邮件 / 飞书
```

**停下条件**：

```text
- 如果 AI 没按专家视角回复（语气像通用助手）：检查是否真的点了"召唤专家"进入对话，而不是普通对话框
- 如果产出明显跑偏：换个更贴任务的专家重试，或把任务描述写更具体
- 如果提示积分不足：专家消耗积分，先看第 3 步的积分说明，或换个轻量任务
```

### 1.4 这一步让你体会到什么

Claude Code / Codex 没有专家这种"角色化预设"机制——你要让它们扮演财务专家，得自己写很长的系统 Prompt 去定义人设、方法论、工具链。**WorkBuddy 把这件事做成了开箱即用的卡片，点一下"召唤"就行**。这是它跟那两个工具的第一个本质差别。

## 第 2 步：看一眼专家团（体会"多专家协同"）

老金这一步不让你真跑（专家团积分消耗是单专家的 3-5 倍，第一次别浪费），只让你**看清楚这个机制**——它是 WorkBuddy 跟 Claude Code/Codex 的第二个本质差别。

### 2.1 什么是专家团

官方定义：**AI 协作团队，自动拆解、并行执行、完整交付**。

打个比方：你让 WorkBuddy 做一份"竞品分析 PPT"，单专家只能干自己擅长的环节（比如财务专家只会看数字）。专家团则是**团长**（一个调度专家）自动把任务拆给市场专家、财务专家、设计专家并行干，最后合并成一份完整 PPT。

### 2.2 操作路径（只看，不召唤）

```text
左侧栏 → 专家中心 → 切换到 "专家团" 分类
    → 浏览专家团卡片（显示：能力介绍、擅长领域、团队成员、任务示例）
    → 读几张卡片，找一个你真实工作里会用到的场景
```

### 2.3 什么时候值得用专家团

```text
✅ 复杂任务，单一岗位干不完（竞品分析、市场调研、多部门汇报）
✅ 一次产出多形态成品（Word 报告 + Excel 数据 + PPT 汇报）
✅ 重要任务，值得花 3-5 倍积分换端到端交付
```

```text
🚫 简单任务（写封邮件、整理表格、改个文档）→ 用单专家甚至直接对话就够
🚫 第一次试用 → 先把单专家跑熟，再来碰专家团
🚫 积分紧张时 → 专家团会很快烧光配额
```

### 2.4 这一步让你体会到什么

Claude Code 有 Subagent、Codex 有多 Agent，但**它们的多 Agent 是开发者自己拼装的、要写配置文件的**。WorkBuddy 的专家团是**预组好的、点一下"召唤"就并行干活的**。这又是"开箱即用 vs 深度可控"的差别。

## 第 3 步：搞清账号、积分和定价（避免踩坑）

老金把这部分放在第 3 步，是因为前面两步你已经在用专家了，积分在烧。必须让你心里有数。

### 3.1 WorkBuddy 的多端形态

WorkBuddy 不只是桌面 App，它是**多端产品**：

```text
- 桌面 App（Windows / macOS）：主力工作台
- 微信 / 企业微信：远程触发、接收推送、跨端接力
- 微信小程序：手机上继续任务、快速查看
```

同一个腾讯账号打通多端，任务可以在一端发起、另一端继续。

### 3.2 账号体系

```text
- 个人用户：微信扫码登录，用个人订阅
- 团队用户：企业管理员开通，按席位计费
- 企业版（私有云）：私有部署，数据驻留可控
```

**WorkBuddy 与 CodeBuddy 同账号同团队**——一个腾讯账号两边通用。订阅关系和套餐互通规则以官网当前说明为准，不要套用旧文档。

### 3.3 积分（最关键的消耗单位）

WorkBuddy 用**积分**计费，不是按次数。关键事实（官方文档原文）：

```text
- 单专家：基础积分消耗
- 专家团：积分消耗通常为单专家的 3–5 倍
- 不同模型消耗不同（旗舰模型积分高）
```

**实操建议**：

```text
- 登录后第一件事：在"我的"或"设置"里看当前积分余额
- 第一次试用：先用单专家跑几个小任务，摸清消耗速率
- 别一上来就召唤专家团：3-5 倍积分很容易烧光配额
- 积分快没了：优先保重要任务，关掉后台自动化
```

### 3.4 价格（只能给个框架，具体数字以官网为准）

```text
- 个人订阅：月费或年费，送积分额度
- 企业 Team：按席位/月
- 私有云企业版：单价更高（2026-05-15 起有过价格调整）
```

> ⚠️ **注意**：**价格、积分额度、套餐结构会变**。腾讯会调整套餐、改积分规则、改免费额度。**任何具体数字以 workbuddy.ai / codebuddy.cn/work / cloud.tencent.com 当下显示为准**，不要把教程里的描述当成实时事实。

## 第 4 步：判断你是不是目标用户

老金在这一步把"该不该用 WorkBuddy"的边界划清楚，因为选错工具比不选工具更糟。

### 4.1 WorkBuddy 适合你，如果

```text
✅ 会用 Word/Excel/企业微信，但不会命令行
✅ 想用 AI 办公，被 Claude Code/Codex 的英文 CLI、API Key 劝退过
✅ 团队在国内，主要沟通是企业微信/微信/QQ
✅ 不想折腾代理、海外信用卡、英文文档
✅ 想要下载就能用、像用微信一样简单的 AI 助手
✅ 是开发者，但身边有非技术同事/家人需要 AI 工具
```

### 4.2 别选 WorkBuddy，如果

```text
❌ 你要做大型代码库重构、复杂架构 → Claude Code（本仓库有教程）
❌ 你要 App + CLI + Cloud 多入口分层协作 → Codex
❌ 你要写 Hooks / Subagent / Agent SDK 做深度定制 → Claude Code
❌ 你要完全本地部署、零云依赖 → OpenClaw
❌ 你团队在海外、用 Slack/Notion/Stripe → Codex / Claude Code
```

### 4.3 三句话总结本质差别

```text
Claude Code / Codex = 给开发者的专业工具，深度可控，要学要配
WorkBuddy           = 给中国办公人的开箱即用助手，专家团技能全预置
两者解决的不是同一个问题，可以共存，不用二选一
```

## 第 5 步：和 Claude Code / Codex 的核心差别对照

老金把这一节留给你做决策参考。**不是优劣对比，是定位对比**——同一个仓库里的四条主线，是"不同人不同工具"的关系。

| 维度 | Claude Code / Codex | WorkBuddy |
|---|---|---|
| **目标用户** | 开发者 | 办公人、非技术用户、国内团队 |
| **形态** | CLI / App+CLI+Cloud 分层 | 桌面 App + IM + 小程序 |
| **登录** | API Key / 海外账号 | 微信扫码 |
| **角色化机制** | 自己写 Subagent 配置文件 | **专家卡片，点"召唤"就用** |
| **多 Agent 协同** | 自己拼、要写配置 | **专家团，团长自动拆解并行** |
| **能力扩展** | Skills / MCP（开发者向） | **技能市场一键安装** |
| **生态集成** | GitHub / Slack / Discord（海外） | **腾讯文档 / 腾讯会议 / QQ 邮箱 / 企业微信** |
| **语言** | 英文为主 | 全中文 |
| **网络** | 部分用户要代理 | 国内直连 |
| **支付** | 海外信用卡 | 微信/支付宝（人民币） |

> 💡 **关键理解**：Claude Code/Codex 强在"深度可控"，你能精确干预每一步；WorkBuddy 强在"开箱即用"，你不用知道任何技术细节就能用上专家团。**两者不冲突**——开发者可以在写代码时用 Claude Code，在写周报/调研/汇报时用 WorkBuddy。

## 常见问题

### Q1：WorkBuddy 能完全替代 Claude Code / Codex 吗？

不能。WorkBuddy 的 Coding Mode（看 WB-08）适合小改、demo、原型，不适合大型代码库重构、CI/CD、深度调试。**它是互补，不是替代**。

### Q2：我已经订阅了 Claude Code / Codex，还要再用 WorkBuddy 吗？

看场景。如果你只有写代码需求，Claude Code/Codex 够用。如果你有大量非代码办公任务（周报、调研、PPT、企业微信分发），或者要给非技术同事一个 AI 工具，WorkBuddy 互补。

### Q3：专家团的积分消耗那么高，值得用吗？

复杂任务值得（一次产出多形态成品、端到端交付），简单任务不值得（单专家甚至直接对话就够）。第一次试用别用专家团，先把单专家跑熟。

### Q4：WorkBuddy 真的不用代理吗？

国内服务器直连，正常办公网络不用代理。具体网络环境以你本机实测为准——少数企业内网可能有自己的出口策略，跟 WorkBuddy 本身无关。

### Q5：腾讯生态集成到底接了哪些？

官方连接器文档（2026-08-06 核对）已支持：QQ 邵箱、腾讯文档、腾讯乐享、腾讯会议、TAPD，可自定义 MCP。企业微信有长链接稳定接入。具体接入步骤看 WB-05。

### Q6：我要给整个团队部署，怎么算账号？

看 WB-09 企业安全章节，按席位计费、集中管理。本篇先解决"个人能不能用起来"的问题。
