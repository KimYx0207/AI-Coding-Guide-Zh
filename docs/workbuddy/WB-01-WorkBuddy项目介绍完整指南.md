### 按需试一次设计创意

需要做海报或 PPT 时，可以在**新建任务 → 设计创意**中查看 WorkBuddy 与 Ardot 的画布能力。首次会要求连接 Ardot，先看清画布读取、编辑与云端同步的授权范围；设计稿保存在云端，练习用虚构内容即可。看不到入口时先查当前账号开放范围，不必为本篇周报练习开通新服务。

可以选“色块占位”，先提出一个小任务：“为虚构的星桥读书会做一张海报，文字只有‘星桥读书会’和‘每周分享一本书’，先给简洁草稿。”核对两行文字后，再框选标题要求调整大小。需要精修时，画布顶部有**用浏览器打开进行编辑**；PPT 类产物可在 Ardot 编辑器下载 PPTX 或 PDF，再用本地软件打开检查。这里只给跟练方法，没有把样例写成实际生成结果，积分与活动奖励也按当前页面确认。完整操作见 [官方设计创意说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Design-Idea)。

## 第一步：召唤一个 AI 专家，让它帮你写周报（15 分钟）

这一步先选一个写作类专家，用同一份工作记录完成起草、核对和修改。

### 1.1 先理解"专家"是什么

WorkBuddy 里有个概念叫**专家**——简单说，就是给 AI 配一个具体职业身份，让它用那个职业的眼光干活。

比如处理销售数据时，可以选择提供表格分析方法的专家。专家卡片里的方法和工具能帮助你组织任务，结果是否可靠，还要回到原始数据核对。

一个专家身上有三样东西（老金给你翻译成大白话）：

- **人设**：它是谁（财务专家、营销专家、写作专家）
- **方法论**：它怎么思考（财务专家看数据先看异常，营销专家看转化先看漏斗）
- **工具链**：它能调什么（写作专家能调文档生成，数据专家能调表格计算）

### 1.2 怎么召唤

打开 WorkBuddy 桌面 App，在左侧栏进入**专家·技能·连接器 → 专家**。一级菜单没有时先检查“更多”，再按 1.5 节查看自定义菜单和当前应用范围。进入专家页面后，浏览与你的任务有关的卡片，查看以下信息：

- 这位专家**擅长什么**
- 它**能帮你做**哪些事
- **使用示例**（给你参考怎么提问）

老金建议你第一次选一个简单实用的——比如"办公写作专家"或"会议纪要专家"。找到合适的卡片后，点上面的**召唤**按钮（可能叫"召唤专家"或"开始对话"），就进入对话界面了。

### 1.3 把任务交给它

没有自己的素材也能跟练。把下面的完整任务粘贴进去；材料文件在 [星桥项目工作记录](../../examples/office-lab/work-notes.md)，之后可以复用。

```text
请根据下面的虚构工作记录，起草星桥项目 2026-09-07 至 2026-09-11 的周报。

N1：林一完成登录页文案第二稿，尚未联调，不能算页面已上线。
N2：叶青修复 CSV 导出的两个问题，使用 12 行样例复测通过；尚未做大文件测试。
N3：许宁收集到 5 条体验课反馈，其中 3 条提到安装步骤长，2 条找不到练习材料。只代表这 5 条反馈。
N4：数据看板共 3 个页面，已完成 2 个；筛选页缺少日期范围定义，负责确认需求的人尚未指定。
N5：演示原定 9 月 14 日，已调整到 9 月 16 日，林一负责组织。下周先确认筛选规则，再做联调和演示准备。

写给项目负责人，控制在 300 字以内，分“本周进展、待协调、下周计划”。
保留数字、未完成状态和改期信息，负责人未给出的写“待确认”。
只用这些记录，不补写增长率、利润或最终上线日期。先给我草稿，不发送。
```

### 1.4 你会看到什么

回复的措辞可以不同，事实应能与记录对上。下面是本课程编写的一份参考稿：

```text
星桥项目周报｜9 月 7 日—11 日

本周进展：登录页文案第二稿完成，尚未联调。CSV 导出修复两个问题，
12 行样例复测通过，大文件测试待做。看板完成 2/3 个页面。
收到 5 条体验课反馈：3 条提到安装步骤长，2 条找不到练习材料。

待协调：筛选页日期范围未定义，需求确认负责人待定。

下周计划：先确认筛选规则，再联调并准备演示。
演示已由 9 月 14 日调整到 9 月 16 日，林一负责组织。
```

读这份稿时，先找三个地方：联调有没有被写成已完成，演示日期有没有用新版，缺失的负责人有没有被编出来。5 条反馈也不能被改写成“多数用户都这样认为”。

如果结果写成“登录页已上线，9 月 14 日演示”，在原任务里继续说：

```text
请只修正两处事实：N1 说的是文案完成、尚未联调；N5 已把演示改到 9 月 16 日。
其他已核对的内容保留，给我修改后的周报，并指出对应依据。
```

确认内容后，可以继续要求“保存为 Word 草稿，文件名为星桥周报-2026-09-11.docx”，打开文件看一遍段落和日期。这样你会得到能带走的文件；对外发送由你决定。文档生成与追加修改的操作可对照 [官方文档实战](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Practice-Cases/Practice-Two)。

最后换一道题：把 N4 改成“筛选规则已由许宁确认，页面仍未完成”，自己写一句追加要求。修改后的稿子应去掉“负责人待定”，同时保留“页面未完成”。做完这个变化，再换成你自己的工作记录。

### 1.5 如果卡住了怎么办

老金把第一次可能踩的坑列出来，你照着排查：

```text
❌ 没看到"专家"入口
   → 先找左侧栏的“专家·技能·连接器”，也检查“更多”里有没有该入口
   → 左侧菜单可右键打开“自定义菜单”，查看入口是否被收进了“更多”
   → 若这些能力当前都不可用，客户端也可能隐藏空入口；再核对当前应用和账号开放范围

❌ 召唤了但回复跟普通 AI 一样，没专业感
   → 确认你是不是真的点了"召唤专家"进对话，而不是进了普通对话框
   → 换个更贴合任务的专家（比如写代码的事别找写作专家）

❌ 提示"积分不足"
   → 专家会消耗积分（下面第三步会详细讲积分）。先看你的积分余额，
     或换个更轻量的任务

❌ 产出明显跑偏
   → 大概率是任务描述太模糊。把"帮写周报"改成"帮我把这三件事整理成 300 字周报"
```

### 1.6 这一步你体会到了什么

专家卡片提供了现成的方法和工具，省去了一部分设置工作。这次更值得记住的是：提供材料、核对关键事实、指出具体差异，再把结果保存下来。换一个专家或另一类文档，这个过程仍然适用。

## 第二步：看一眼专家团，理解"多角色协同"（5 分钟）

这一步先看懂专家团的分工机制，再决定是否试跑。多角色协作可能增加处理量，第一次试用先用小任务观察实际积分消耗。

### 2.1 什么是专家团

**专家团**就是多个专家分工协作，一起干一件复杂的事。它有一个**团长**（也是一个 AI 角色，相当于项目经理），你只要把任务告诉团长，团长会自动：

```text
1. 把你的任务拆成几个子任务
2. 分配给最合适的几个专家
3. 这些专家并行（同时）干活
4. 团长把所有人的产出合并成一份完整成果
5. 返回给你
```

例如做竞品分析时，可以让不同角色分别整理市场资料、比较财务信息和编排汇报内容，再合成报告。是否需要专家团，取决于任务能否合理拆开、所选团队提供哪些工具，以及你是否能核对每部分的来源。

### 2.2 怎么找到专家团

回到**专家中心**（刚才召唤单专家的地方），切换到**专家团**分类。你会看到专家团卡片，上面写着：能力介绍、擅长领域、团队成员（这个团里有哪几个专家）、任务示例。

老金建议你浏览几张卡片，找一个跟你工作相关的场景读一读任务示例，你就明白什么情况下值得用专家团了。

### 2.3 什么时候该用专家团

```text
✅ 值得用（积分花得值）：
   - 复杂任务，单一岗位干不完（竞品分析、市场调研、大型汇报）
   - 一次要出多种形态的成果（Word 报告 + Excel 数据 + PPT 汇报）
   - 重要任务，需要多个角色协作，且能接受试跑后的实际积分消耗

🚫 不值得用（白烧积分）：
   - 简单任务（写封邮件、整理个表格、改个文档）→ 用单专家甚至直接对话就够
   - 第一次试用 → 先把单专家跑熟，再来碰专家团
   - 积分紧张时 → 先看小任务的实际消耗，再决定是否增加角色和处理量
```

### 2.4 进阶玩法：自建专属专家团

现成专家团不适合你的任务时，先参考 [WB-03 的配置草稿](./WB-03-WorkBuddy专家与专家团完整指南.md#42-怎么建用引导对话)设计角色和分工。当前账号提供自定义创建入口时，再按页面创建、保存并试跑；只有一份对话草稿时，还不能算已经建好专家团。

### 2.5 这一步你体会到了什么

Claude Code 和 Codex 也支持多 Agent，可以按任务请求分工；自定义角色与协作规则时才需要进一步配置。不能简单地说它们都要先手写一套编排。

WorkBuddy 这条课程先从现成专家团的卡片和任务示例入手。你要判断的是它是否适合当前任务、分工是否清楚，以及合并后的成果有没有漏掉事实。

## 第三步：搞清账号、积分和价格（别踩坑）

老金把这部分放在第三步，是因为前两步你已经在烧积分了，必须让你心里有数。这一节信息量大，但都是掏钱决策的关键，耐心看完。

### 3.1 WorkBuddy 的多端形态

WorkBuddy 不是只有一个桌面 App，它是一套**多端产品**：

```text
- 桌面 App（Windows / macOS）：主力工作台，功能最全
- 微信 / 企业微信：远程触发、接收推送、跨端接力
- 微信小程序：手机上继续任务、快速查看
```

多端使用先确认同一 WorkBuddy 账号和对应任务，再按 [WB-08](./WB-08-WorkBuddy多端协同完整指南.md) 完成一次手机查看与继续对话的验证。企业微信还要配置助理或通知通道，不能只凭同微信登录就保证所有配置与本地材料已经同步。

### 3.2 WorkBuddy 和 CodeBuddy 的关系

腾讯这两个产品经常被搞混，老金一句话讲透：

```text
CodeBuddy = 管写代码（编程助手，类似 Cursor、GitHub Copilot）
WorkBuddy = 管办公（AI 员工，帮你出文档/报表/调研/汇报）
```

WorkBuddy 和 CodeBuddy 有关联账号关系，但是否共用当前订阅、可用积分和产品权限，要分别核对两个产品的账户与套餐页面。不要只凭同一登录账号就推定订一份能使用全部功能。

### 3.3 积分是什么、怎么扣

WorkBuddy 不按"次数"计费，而是按**积分**计费。积分你可以理解成"AI 干活的能量额度"，类似游戏里的钻石：

- 你每月有一批积分额度（按订阅套餐给）
- 每次召唤专家、用技能、跑专家团，都扣积分
- 积分消耗随模型和任务处理量变化，先用小样本试跑，再按「订阅和用量」中的实际记录评估预算
- 积分用完了任务就跑不动，要么等下个月、要么加购

**积分消耗优先级**（先扣哪个）：先用免费体验额度，再按到期顺序扣赠送积分，最后扣付费积分。

### 3.4 价格大概多少（核查日：2026-09-14）

以下保留的是 **2026-09-14 的报价快照，不代表 2026-10-03 的现价或当前赠送权益**。本次访问官方定价页未能取得正文，所以不把旧表写成重新核实的报价。决定购买前，核对 [当前定价页](https://www.workbuddy.cn/docs/workbuddy/Pricing)、订单页和“订阅和用量”中的套餐权益。

|------|------|------|--------------|

**怎么选**：


### 3.5 查看你的积分余额

登录后，先点击左侧栏底部的头像，进入**查看积分余额**，或打开**设置 → 套餐与积分**。5.4.7 的更新日志曾将该页称为「订阅和用量」，本机仍显示这个名称时就进入该页。核对当前套餐、余额和用量后，先用一项小任务观察消耗，再决定是否付费。

## 第四步：判断你是不是 WorkBuddy 的目标用户

老金在这一步把"该不该用 WorkBuddy"的边界划清楚，因为选错工具比不选工具更糟。

### 4.1 WorkBuddy 适合你，如果

```text
✅ 会用 Word / Excel / 企业微信，但不会命令行
✅ 想用 AI 办公，但被各种 AI 工具的英文界面、API 配置劝退过
✅ 团队在国内，主要沟通是企业微信 / 微信 / QQ
✅ 不想折腾代理、海外信用卡、英文文档
✅ 想要下载就能用、像用微信一样简单的 AI 助手
✅ 是开发者，但身边有非技术同事、家人需要 AI 工具
✅ 想给团队部署一个低门槛、中文友好、贴合国内生态的 AI 办公工具
```

### 4.2 别选 WorkBuddy，如果

```text
❌ 你要做大型代码库重构、复杂架构设计 → 用 Claude Code（本仓库有教程）
❌ 你要命令行、API、多入口（CLI+Web+Cloud）深度协作 → 用 Codex
❌ 你要写 Hooks、Subagent、Agent SDK 做自动化定制 → 用 Claude Code
❌ 你要求本地处理、少用云服务 → 可评估 OpenClaw 与本地模型，但要逐项检查工具和服务依赖
❌ 你团队在海外、主要用 Slack / Notion / Stripe → 用 Codex 或 Claude Code
```

### 4.3 WorkBuddy 现在的缺点（不吹不黑）

选型时，先用自己的小任务检查这几件事：

```text
- 能否配置你需要的专家、技能和连接器
- 复杂任务的实际用量是否符合预算，是否出现反复重跑
- 代码或文件成果能否接入你现有的编辑、测试与审查流程
- 更换外部服务后，授权和数据访问是否仍满足工作需要
```

这些问题需要实际任务记录来回答。本课程没有提供四款工具的统一性能测试，不能据此给出固定的能力排名。

## 第五步：跟其他 AI 工具的差别（一表说清）

老金把这一节做得尽量短——详细对比留给 WB-10，这里只给你一个快速决策参考。

| 维度 | Claude Code / Codex | WorkBuddy |
|---|---|---|
| **给谁用** | 开发者 | 办公人、普通人、国内团队 |
| **形态** | 命令行、多入口分层 | 桌面 App + 微信 + 小程序 |
| **怎么登** | Claude Code 支持适用订阅/Console；Codex 支持 ChatGPT 账号或适用 API 认证 | 官网登录页支持微信、手机号、邮箱、SSO 等 |
| **角色化** | 可用子代理角色，按任务选择或配置 | 从专家卡片选择当前可用角色 |
| **多 AI 协作** | 可按请求与项目指引委派子任务，检查分工和合并结果 | 从专家团卡片开始，检查实际分工与成果 |
| **能力扩展** | Skills / MCP（技术向） | 技能市场一键装 |
| **生态** | GitHub / Slack / Discord（海外） | 企业微信 / 腾讯文档 / QQ 邮箱（国内） |
| **环境与计费** | 按具体入口、账户地区、认证和所用服务确认 | 按官网可用登录方式、当前套餐及企业网络规则确认 |

一句话总结：**Claude Code / Codex 是深度可控的专业工具，WorkBuddy 是开箱即用的办公助手，两者解决的不是同一个问题，可以共存**。老金自己写代码用 Claude Code，写周报、做调研、出汇报用 WorkBuddy——根据任务选工具，不二选一。

## 常见问题

**Q1：WorkBuddy 能完全替代 ChatGPT / Claude 吗？**
不能完全替代。先用你常做的一项任务比较材料处理、结果文件、外部服务接入和用量，再决定是否需要多款工具。不能把 ChatGPT 或 Claude 一概当成只有聊天问答；本系列重点教 WorkBuddy 的办公流程，不提供统一性能排名。

**Q2：我已经订了 ChatGPT Plus / Claude Pro，还要订 WorkBuddy 吗？**
先用现有订阅完成一项周报、调研或文件任务，再比较 WorkBuddy 是否补上你需要的腾讯服务接入、手机协同或现成专家流程。只有这些差异确实能减少整理工作，并且用量符合预算时，再决定是否增加订阅。

**Q3：专家团消耗积分那么高，值得用吗？**
复杂任务值得（一次出多种形态成果、一次交付完整），简单任务不值得（单专家甚至直接对话就够）。第一次试用别用专家团，先把单专家跑熟。

**Q4：WorkBuddy 真的不用翻墙吗？**
国内服务器直连，正常办公网络不用翻墙。具体网络环境以你本机实测为准——少数企业内网可能有自己的出口策略，跟 WorkBuddy 本身无关。

**Q5：腾讯生态接了哪些？**
目前接通的有 QQ 邮箱、腾讯文档、腾讯乐享、腾讯会议、TAPD（腾讯的项目管理工具），企业微信有稳定接入，还能自己加自定义连接器。具体怎么接看 WB-05。

**Q6：我要给团队部署，怎么算账号？**
看 WB-10。团队场景按席位计费、集中管理，企业版还能私有部署。

**Q7：AI 会不会读我的隐私数据？**
文件和工具访问取决于所选工作空间、权限模式、已启用能力及具体任务。先看实际操作提示和变更记录，不能只凭专家名称判断它可访问什么；接通外部账号后还要核对对应授权范围。涉及工作材料时，先按 [WB-10](./WB-10-WorkBuddy企业账号安全与对比完整指南.md) 确认团队的数据处理要求。
