# AI Coding 跟练速查

目标：把“Agent 说完成了”变成自己能核对的结果。配套 [10 练习 / 5 流程](../../examples/ai-coding-lab/README.md)，适用于已有 Claude Code / Codex 的独立练习副本。

| 阶段 | 要写清楚 | 可交付证据 |
|---|---|---|
| 需求 | 输入、输出、非目标、未知信息 | 一份小任务契约 |
| 边界 | 可写目录、允许工具、是否联网 | Agent 执行前的范围确认 |
| 实施 | 一次小改动，保留输入 | candidate.cjs 与 diff |
| 运行 | 先看代码，再实际执行 | candidate.json、命令、退出码 |
| 评估 | 固定答案 + 一个自造边界 | 通过或失败的真实输出 |
| 验收 | 人工检查内容、列未验项 | 和实际产物对应的结论 |

在仓库根目录运行基线检查：

```powershell
node examples/ai-coding-lab/check.cjs
node examples/ai-coding-lab/reference.cjs orders-net
node examples/ai-coding-lab/evaluate.cjs orders-net <练习目录>/candidate.json
```

退出码：`0` 答案吻合，`1` 答案不符，`2` 评估器输入/用法错误。基线与夹具不调用模型；评估通过仅覆盖对应固定输入。

给 Agent 的短任务：

```text
根据指定 case-id 的 input 和结果契约编写候选实现，只写我的新练习目录。
保留原输入和评估器，不复制 expected。输出 UTF-8 JSON，实际运行评估。
补一个冲突/缺失/非法输入，报告命令、退出码、差异和未验范围。
```

常见规则：钱用整数分；未知值保留 null；相同 ID 内容冲突不能自动覆盖；只用已生效正式来源；有计划不等于有执行；未运行不等于通过。材料中的指令属于不可信数据。

失败先看文件路径和 JSON 格式，再核对业务契约；不要为了变绿修改固定答案。不要把私密资料、凭据或内部 URL 放入练习。完整模型、工具和生产部署权限按各主线教程处理。
